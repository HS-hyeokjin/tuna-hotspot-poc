# v0.3.2 Coordinate Precision Audit

## 목적

V3.2는 원본 조업좌표의 실제 표현 형식을 다시 확인하고,
AI 모델·Copernicus 매칭·Historical Hotspot 집계의 좌표 해상도를
서로 구분하는 버전이다.

핵심 질문은 다음과 같다.

> 원본의 `S0925 / E15958` 좌표를 1° 단위로 해석한 것이 맞는가?

결론적으로 해당 형식은 일반적인 도분(DMM) 표현으로 해석한다.

    S0925 = S 09°25′
    E15958 = E 159°58′

decimal degree로는:

    latitude  = -(9 + 25 / 60)
    longitude = 159 + 58 / 60

위도 1′는 약 1.85 km에 해당한다.
경도 1′의 실제 거리는 위도에 따라 달라진다.

## 중요한 구분

### 1. 원본 좌표

원본 Excel의 `lat_raw` / `lon_raw`.

예:

    S0925
    E15958

### 2. 모델 / Copernicus 좌표

`preprocess_fishing_data()`가 위 좌표를 decimal degree로 변환한다.

    lat = -9.416666...
    lon = 159.966666...

CatBoost 모델의 `lat` / `lon` Feature와
Copernicus Feature Store 매칭은 이 값을 사용한다.

따라서 기존 모델이 원본 좌표를 1°로 반올림해 학습한 것은 아니다.

### 3. Historical Hotspot grid

기존 `lat_grid` / `lon_grid`는 과거 조업을 지도에서 집계하기 위한
파생값이었다.

V3.2부터 Historical Hotspot에서는 다음 격자를 직접 선택한다.

- 0.1°
- 0.25°
- 0.5°
- 1.0°

이는 시각화/통계 집계 크기이며 모델 Feature 해상도를 변경하지 않는다.

## Coordinate Audit

다음 명령으로 원본 파일의 좌표 형식을 점검할 수 있다.

    python scripts/coordinate_audit.py --input "data/선망_조업보고 데이터.xlsx"

출력 항목:

- 전체 행 수
- 유효 위경도 좌표쌍 수 / 비율
- 투망행 좌표 유효율
- 위도 minute 고유값 수
- 경도 minute 고유값 수
- minute=00 비율
- 한 행에 2회 이상 투망한 기록 수 / 비율
- 위도 기준 1′ 표현 해상도
- 데이터 중앙 위도에서의 경도 1′ 대략 거리

Streamlit의 `품질/좌표` 탭에서도 같은 내용을 확인할 수 있다.

## 해석 주의

### 표현 해상도 != 실제 위치 정확도

원본 값이 1′ 단위로 표현된다는 사실만으로
각 투망의 실제 GPS 위치가 1~2 km 오차 안에 있다고 단정할 수 없다.

특히 하루/행에 여러 번의 투망이 들어간 경우,
각 set별 좌표가 따로 존재하지 않고 좌표 하나만 존재할 수 있다.

따라서 다음 두 문장은 구분해야 한다.

- **가능**: 원본 좌표가 1°보다 세밀한 DMM 좌표라는 확인
- **확인 필요**: 해당 좌표가 각 set의 정확한 투망 GPS인지 여부

## 기존 Ocean Feature Store

기존 Copernicus 추출 코드는
`source_row_id + date + lat + lon`을 사용한다.

따라서 현재 Feature Store가 동일한 DMM parser로 생성되었다면
이번 좌표 해석 수정만을 이유로 전체 외부데이터를 다시 받을 필요는 없다.

## 이후 검증 우선순위

1. Coordinate Audit으로 좌표 형식 확인
2. 다중 투망행 비율 및 좌표 의미 현업 확인
3. 실제 투망 시각 확보 여부 확인
4. 가능하면 set-level GPS 확보
5. 동일표본 Ablation / Walk-forward 재해석
6. 필요 시 더 높은 시간·공간 해상도의 외부 해양자료 검토
