# v0.3.0 Copernicus Ocean Data

## 목적

V2에서 확인한 조업방법·선박·선장·위치·수온·조류 신호에
외부 해양환경 데이터를 추가했을 때 실제 검증 성능이 개선되는지 확인한다.

V3는 미래 어장을 확정 예측하지 않는다.

핵심 질문:

> Copernicus Marine의 해양환경 특징이 기존 조업기록만 사용한 모델보다
> 미래 시점 검증 성능과 Top-K 후보 선별력을 실제로 높이는가?

## 사용 데이터

Copernicus Marine Global Analysis & Forecast의 일자료를 사용한다.

- SST: `cmems_mod_glo_phy-thetao_anfc_0.083deg_P1D-m` / `thetao`
- Current: `cmems_mod_glo_phy-cur_anfc_0.083deg_P1D-m` / `uo`, `vo`
- Sea Surface Height: `cmems_mod_glo_phy_anfc_0.083deg_P1D-m` / `zos`
- Chlorophyll-a: `cmems_mod_glo_bgc-pft_anfc_0.25deg_P1D-m` / `chl`

조업자료의 날짜·좌표에서 가장 가까운 일자료 격자를 사용한다.

## 생성 특징

- ocean_sst
- ocean_current_u
- ocean_current_v
- ocean_current_speed
- ocean_current_dir_deg
- ocean_ssh
- ocean_chl
- ocean_sst_gradient_c_per_100km

SST Gradient는 조업위치 주변 약 0.25도 동서남북 SST를 이용한
중심차분 기반 근사값이며, 단위는 약 °C / 100 km이다.

## 날짜변경선 처리

조업좌표가 E179와 W179처럼 날짜변경선을 가로지를 수 있으므로
전체 최소/최대 경도로 하나의 bbox를 만들지 않는다.

월별 + 경도 20도 + 위도 20도 블록으로 분리한 후 Copernicus 원격 데이터를 읽는다.
따라서 -180/180 경계 때문에 거의 전 지구를 요청하는 문제를 피한다.

## 실행

Copernicus Marine 로그인 완료 후 먼저 소량 테스트:

    python scripts/build_ocean_features.py --limit 100

정상 확인 후 전체 실행:

    python scripts/build_ocean_features.py

결과:

    data/external/processed/fishing_ocean_features.parquet

중간 결과는 다음에 캐시된다.

    data/external/cache/

재실행 시 캐시가 있으면 다시 API를 조회하지 않는다.
강제로 새로 받고 싶으면:

    python scripts/build_ocean_features.py --force

## Streamlit

외부 특징 Parquet이 존재하면 `app.py`가 자동으로 결합한다.

Ocean Data 탭에서:

- 변수별 Coverage
- 조업일지 수온 vs Copernicus SST 비교
- 외부 특징 예시

를 확인할 수 있다.

AI 실험실에는 다음 V3 실험이 추가된다.

- 외부 해양 · 환경 Only
- 외부 해양 · 모든 변수
- 기존 + 외부 해양 · 모든 변수

V2 모델과 동일한 시간분할/Walk-forward 지표로 비교한다.

## 주의

1. 위성 관측값 그 자체가 아니라 모델 분석/예보 제품이 포함될 수 있다.
2. 가장 가까운 일/격자 매칭이므로 실제 투망 시각의 순간 환경과 차이가 있다.
3. 조업시각이 없기 때문에 V3는 일자료를 사용한다.
4. 수온전선 근사치는 센서 관측 전선과 동일한 개념이 아니다.
5. 외부 데이터 추가가 성능을 높이지 않으면 그 자체가 중요한 PoC 결과다.
6. 회사 원본 조업자료와 생성 Parquet은 GitHub에 커밋하지 않는다.
